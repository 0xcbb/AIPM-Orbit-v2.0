# CP17 网络收音机核心说明

## 体验定位

CP17 的核心体验是“网络电台 + 精密仪器 + 桌面待机摆件”。竖屏默认负责纯净播放、频率识别和快速切台；精密调频、收藏、列表、附近电台地图、分享和高级能力退入二级面板；横屏或待机模式负责展示时钟主题、当前电台状态和轻量音频动势。

CP17 保留为内部产品编号、代码包名、文档和本地数据迁移口径；面向用户、APK 标签、分享文案、通知栏、声音明信片和公网落地页统一使用品牌名 `Void Radio`。除非后续单独规划数据迁移，不应为了品牌展示重命名包名、SharedPreferences key 或历史 QA 脚本。

## 视觉原则

- 主界面使用暖灰纸白、石墨灰和深墨绿组成低饱和仪器色盘：主文字为深灰黑，核心交互强调色为深墨绿 `#0D6B5B`；红色只作为播放失败/警示状态和声音明信片“信号点”的点睛色，不作为主 UI 常驻强调色。
- 频率数字必须是界面第一视觉中心，使用超大细体、等宽数字口径和稳定行高。
- 主频率区使用暗色仪器声场承载频率和低透明度动态声波；`100.3 / NET` 后方可以出现随播放态轻微跳动的墨绿 / 旧金属灰音波，但不得再叠加复杂圆环、斜指针、大面积竖向装饰波或多余状态信息。
- 主频率数字允许加入极轻微 VFD 荧光管呼吸感，透明度变化应缓慢、低幅度，只强化“安静仪器仍在工作”的生命感，不得做成闪烁、警报或高频动效。
- 主屏快捷按钮与底部快切轨之间的迷你调谐台采用水平手动调谐条：轨道负责浏览当前国家/地区可用候选电台，候选按真实 FM 频率优先排序，松手或点击轨道后切台；切换底部推荐频道或地图点播后，调谐条必须立刻同步到当前电台所在国家和刻度位置。调谐条应自然落在主屏空白纸面中，不使用突兀的悬浮卡片、厚阴影或强边框包裹；同时不能窄成一根孤立细线，应有足够触控高度、完整横向刻度、当前电台文本和轻微仪器槽体感。首页不承载 100.3 -> 100.2 -> 100.1 这种空频自由扫描；完整 0.1 精度拟物调谐可作为二级专业面板。
- 控件保持克制、低噪音、高密度；主屏常驻内容以频率、FM 标识、电台名、当前曲目、当前电台地区、低噪音选项入口、播放控制和一组精致快捷图标为主，不做营销页式 hero，不使用装饰光球。
- 主界面不得绘制假的系统状态栏，不应在页面内模拟时间、信号、耳机模式或电量；正式移动端应使用系统原生状态栏，并通过安全区和状态栏颜色控制保证页面顶部留白。
- 当前电台地区只允许作为主屏顶部左侧的低对比文本出现，与右侧“选项”入口同一视觉层级；例如 `UFM 100.3` 应显示 `新加坡`，长地区名称必须单行截断，不能与选项入口或主频率区重叠。
- 主屏顶部左侧地区文本同时承担低噪音国家切换入口；点击后必须弹出中文国家列表，并进入对应国家的 Radio-Browser 发现目录，不能只作为静态装饰文本。
- 当前曲目必须作为页面上的自然文本信息呈现，可带小型音乐图标；播放中必须优先使用真实 `ICY metadata`、官方播放 API 或后端代理。V1 对非 HLS 直播流必须显式请求 `Icy-MetaData: 1`；UFM 100.3 的 StreamTheWorld 源优先读取 ICY，ICY 暂时缺失时使用 Triton Digital 公共 Now Playing XML 作为同一官方播放平台的备用元数据源，并更新为真实“歌手 - 歌名”。当所有真实元数据暂时不可用时，只允许显示“正在获取曲目信息”等中性状态，不得轮播本地假歌名误导用户或触发歌词查询。
- 主屏可在当前曲目附近加入极小字号的 `LOCAL / SIGNAL` 时间错位提示，用电台经纬度在本地估算信号源时间，强化“我的深夜，你的清晨”的平行时空感；该信息只能作为低噪音仪器刻字存在，不能变成新的状态卡片或抢占电台名 / 频率层级。
- 主屏快捷图标允许承载收藏、喜欢、床头钟、隔空播放、附近电台等即时动作；图标应收进低矮嵌入式仪器工具条，使用轻边框、弱分隔线和低饱和选中态，避免五个独立悬浮圆钮造成页面浮层过多。该工具条不得承载第二个设置入口，不能占据主视觉。
- 主屏必须提供低噪音的精选电台快切入口，让用户不进入调谐设置也能直接切换常用电台；该入口应小尺寸、可横向滚动，可以保留精致的轻浮雕频道 chip 和选中态质感，但不能变成厚重悬浮卡片墙。选中态使用深墨绿文字、轻量图标、淡冷绿底或极弱阴影表达，不得削弱频率数字、调谐槽和播放按钮的主层级。
- 精选电台快切优先展示 `PlaybackItem.artwork` / Radio-Browser `favicon` 提供的远程台标，统一放入固定尺寸圆角方形容器，避免不同图片比例改变 chip 布局。仅尝试 HTTPS 图片；HTTP 地址可在客户端升级为 HTTPS 后尝试，升级失败、空地址或加载错误时必须稳定回退为电台名首个有效字符。不得把第三方电台官方 Logo 打包进 App，避免版权、更新和安装包膨胀风险。
- 主屏快捷按钮与底部快切轨之间允许放置低矮“迷你调谐台”，用于滑动浏览当前国家/地区的 Radio-Browser 电台；它必须保持横向仪器刻度感、低信息密度和清晰吸附反馈，不得恢复占满首屏的大型机械刻度盘。
- 横屏首页不得直接复用竖屏纵向堆叠，避免电台横滑卡片、播放控制和主频率卡相互遮挡。横屏应切换为分栏仪器布局：主频率卡、当前电台信息、嵌入式动作工具条、薄信号状态条、底部电台轨和紧凑播放控制各占独立区域；横屏低高度下不展示完整迷你调谐卡，避免被底部频道轨或播放控制截断。
- 附近电台地图页使用低饱和地图、低噪音定位点和单一底部控制抽屉；V1.1.3 默认“暖金石墨”主题采用暖炭墨底、香槟金交互点和暖石墨瓦片滤色，定位钮、分段激活态、播放动作与 marker 脉冲统一使用金色。Polar Graphite 等冷色主题继续保留冷灰地图。所有主题都不得回退成普通旅游 App 式彩色底图。地图中只保留返回、重新定位、定位状态和少量 marker，国家/城市切换、筛选、电台列表和播放动作收进抽屉内，不能堆叠多个浮层卡片或变成复杂频道广场。抽屉默认态必须保留地图空间感，建议初始高度控制在约 38% 屏幕高度；上滑态应接近全屏并采用精致目录密度，方便连续浏览电台；抽屉顶部把手和标题区必须也能响应上滑，不能只在中间列表区域才拖得动。
- 图标必须来自图标库或系统资源，不使用随手绘制的占位图标。

## 交互原则

- 主屏迷你调谐条必须支持手指拖拽、轨道点击和候选吸附；移动端后续可补充系统 haptic，Web 原型可用 `navigator.vibrate` 模拟。
- 移动端关键操作应提供克制的系统触感反馈：播放/暂停、上一台/下一台、收藏、喜欢、设置、隔空播放、附近电台、国家/城市选择、地图定位、地球背面、地图电台点播和调谐条吸附可使用轻微 selection / light impact；地图拖拽、抽屉滚动、列表连续滑动不得持续震动，避免破坏精致感。
- 专业调频面板如继续保留 0.1 FM 精度调节，应收纳在二级设置中，不能重新占据主屏主要版面。
- 播放/暂停、切台、收藏、喜欢、床头钟、隔空播放和附近电台可以作为主屏即时操作；顶部“选项/设置”保留完整二级入口。主屏中部工具栏不得同时出现两个设置入口；分享明信片在传播闭环成熟前不作为主屏高频按钮，应收纳在设置 / Now Playing / 分享面板中。
- 设置页必须按“收听 / 仪器 / 发现与分享”分组组织，优先承载真实可用的小功能：睡眠定时、启动自动播放、数据节省模式、触感反馈、歌词 Beta、电台库、全球搜索、导入列表、附近电台、私人微电台和分享入口。未实现的高级能力（闹钟、天气主题、录音、CarPlay/Android Auto、SMB/DLNA 自动发现）可以记录为规划，不得以可点击真功能形式误导用户。
- 正式 Flutter App 中，分享按钮应优先生成“声音明信片”而不是只分享文本链接；该能力必须零后端、本地离线渲染，并调用系统原生分享面板。
- 声音明信片分享必须同时附带可复制/可点击的播放链接；零后端阶段优先使用静态 HTTPS 落地页承载可播放声音卡片，未配置公网落地页时允许回退分享直连 stream URL。微信内聊天卡片直接播放属于平台限制，不能伪装为已实现；正式深链、Android App Links / iOS Universal Links 和平台 SDK 分享卡片属于后续公网能力。
- 声音明信片默认模板必须是 `SIGNAL INTERCEPTED` 信号截获回执，而不是风景明信片、普通音乐分享卡或服务器日志式终端截图。当前 V1.1 视觉口径为白底热敏票据：旧纸白背景、褪色墨水灰、唯一红色信号点、虚线走纸、纸张噪点、极细静态波形、数据区等宽字体和中文旁白衬线体；内容展示频率/NET、电台名、当前曲目、协议/码率估算、信号源坐标、可用时的本机/起点坐标、跨越距离、UTC 时间戳、用户本地时间和信号源当地时间。无坐标电台不得伪造精确坐标，可显示 `DEVICE REDACTED` 或地点/直播流兜底。模板必须继续由本地 `RepaintBoundary` 离线渲染，不引入后端。
- 声音明信片分享文案允许内置少量克制的情绪短句，并按电台、时间、坐标做稳定轮换，例如“我的深夜，你的清晨。”、“世界另一侧的日常，刚好穿过我的房间。”；文案应服务于“安静仪器扫描世界电台”的孤寂感，不得变成鸡汤、营销口播或高频弹窗。用户/地球背面模式传入的 `storyLabel` 优先级高于默认开场白，但不应移除可播放链接。
- 附近电台地图页必须允许用户从当前城市电台中选择播放，并提供手动国家/城市切换；点击定位时应优先使用真机/浏览器经纬度居中地图，并按 `geo_lat / geo_long / geo_distance` 查询 Radio-Browser 附近电台，再尝试反查城市和国家码；附近结果不足时补城市/国家目录。定位失败、定位服务关闭或授权拒绝时，不得让地图页停在错误态，应回退到当前国家/默认城市目录、显示可用 marker，并允许用户拖拽缩放或手动选择国家/城市。自动定位失败不得弹出强错误感黑色提示；用户正在点 marker 或进入地球背面模式时，旧定位请求不得覆盖当前模式或弹出“未获取当前位置”。
- 地图页允许提供“地球背面电台”故事化发现模式：根据用户真实位置或当前地图中心计算对跖点，经纬度规则为 `lat = -lat`、`lng = lng >= 0 ? lng - 180 : lng + 180`，并用 Radio-Browser `geo_lat / geo_long / geo_distance` 逐步扩大半径查找对跖点附近电台；进入该模式时必须立即给出短促触感、按钮忙碌态和精密仪器式数字跳变 / 坐标校准反馈，而不是等定位或远端接口返回后才响应。地球背面请求必须有防连点和请求序号保护，用户连续点击不得排队弹出多个校准页面或让旧响应覆盖新状态。对跖点落海或无结果时，应明确标注“全球热门兜底”或“最近可用电台”，不得暗示一定找到精确当地广播。
- 地图 marker 点击不能只震动或只改变内部状态；点击某个电台点后，地图上必须出现轻量选中信号卡，底部抽屉必须把对应电台提到可见首位并高亮，用户可选择“收听”后再回到主页播放。marker 轻点不默认直接播放，避免误触切台。
- 附近电台地图页中的电台列表行必须可以直接触发播放并回到主屏；点播前列表行只能显示“播放”等动作入口，不能把未播放的第一条远端结果误标为“播放中”；点播后主屏应立即进入连接、LIVE 或明确失败状态，不能停留在暂停状态等待用户再次点击播放。
- 主屏频率 / `NET LIVE` 仪表卡整体必须可点击进入 Now Playing；当前曲目文本可作为辅助入口，但不能成为唯一入口。首页不得显示歌词预览、歌词加载条或歌词卡片，避免破坏仪器主视觉和竖屏比例。
- 横屏待机模式必须保留当前频率、电台名称和播放动势，不能变成纯时钟；同时必须读取系统安全区，关闭按钮、翻页钟主体、底部电台状态和底部手势条之间不得重叠，小时钟应可按可用高度等比缩放。
- 车载模式应作为独立二级模式或 Android Auto / CarPlay 能力规划，不直接塞进首页。车载模式只保留大播放控制、上一台/下一台、当前电台/曲目、收藏和语音/方向盘友好操作，禁止复杂搜索、地图抽屉和密集筛选，保证驾驶安全与低认知负担。

## 数据与播放边界

- 原型阶段使用本地 mock 电台目录，并允许为少量电台接入真实直播流地址和 mock 当前曲目；真实流地址必须标记来源，且需允许播放失败、地区限制、HTTPS/HTTP 混用等不可控情况。
- 当前曲目在主屏必须作为低噪音辅助信息展示，不能抢占频率数字和电台名的视觉层级，也不能用过强容器感制造信息噪音；V1 起不再把精选电台本地节目样例当作播放中曲目轮换。真实元数据未到达时显示获取中/直播节目等中性文案，且必须标记为非真实 metadata，不能触发歌词联网查询；正式阶段继续优先从 ICY metadata、官方播放 API 或后端代理获取。
- 正式 App 阶段优先使用成熟音频库：Flutter 可选 `just_audio` + `audio_service`；React Native 可选成熟音频/后台播放库。
- 电台流地址来源优先级：电台官网公开 stream links / M3U / PLS，其次接入 radio-browser.info 公共 API，再其次用户手动导入本地 JSON/M3U。
- 零后端电台目录采用“双层来源”：首页默认/推荐和主屏快切必须使用本地精选 JSON，保证打开即播和品质稳定；地图页、附近电台和后续搜索使用 Radio-Browser 作为公共目录浏览器，远端同步期间先展示当前国家的本地精选兜底，失败或无结果时必须回退到本地精选/默认城市数据。
- Radio-Browser 数据接入必须保留 `stationuuid`，优先使用 `url_resolved`，筛选 `lastcheckok=1` 且排除明显不可用的 `UNKNOWN` codec；国家切换必须优先同步 Radio-Browser `/json/countries` 国家目录并使用中文地区名展示，内置重点国家作为兜底；地图位置页必须同步 Radio-Browser `/json/states/<country>/` 地区/州/城市目录，并提供独立城市/州/地区搜索框，请求 `/json/states/<country>/<filter>` 时不得把“全部电台”等无关入口排在匹配城市前面；地图页必须支持国家级 `countrycode` 查询、城市/地区级 `countrycode + state/region` 查询、按电台名/标签/地区搜索、经纬度半径查询和 `limit + offset` 分页加载，地区结果不足或为空时必须自动补国家级结果，避免用户误以为公共目录只有少数电台；切换国家/城市时电台集合、地图中心和选中卡必须同步变化，并展示或记录 `codec`、`bitrate`、`countrycode`、`geo_lat/geo_long` 等质量字段；结果应本地缓存，避免每次打开都请求公共 API。
- Radio-Browser 客户端必须使用多个官方 API host 兜底；单个 host HTTP 失败、超时或解析失败后，应进入短期降权 / backoff，后续请求优先使用最近成功 host，避免地图、搜索或语言信号页因单节点不稳而长时间卡住。
- Radio-Browser 异步请求必须携带当前国家、地区/城市、经纬度、搜索词和分页 offset 的快照，并用请求序号丢弃晚返回的旧响应；快速切国家、定位、搜索或加载更多时，旧结果不得覆盖当前地图列表。加载更多失败时不得跳过页码，也不得清空已加载结果回退成首页精选。
- Radio-Browser 结果展示前必须做本地质量排序和坏源降权：优先展示 `lastcheckok=1`、`votes/clickcount` 高、`bitrate` 合理、codec 明确、坐标完整的电台；用户本机标记为不可用的 stream URL 必须降权或过滤，不能继续排在地图列表前列。
- 地图发现页的远端 Radio-Browser 条目在生成 marker 和抽屉列表前必须先通过可播过滤；`UNKNOWN` codec、非 http/https、`lastcheckok=0` 或本地坏源 URL 不得显示为可点击地图点。地图宁可显示更少但可听的点，也不能展示一屏“点得到、听不了”的远端假健康源。
- 从 Radio-Browser 公共目录点播时，必须允许单个流地址失败；如果同一列表仍有候选电台，应自动尝试下一个可播放候选并保持主屏处于连接/明确失败状态，不能让用户反复手动试坏源。自动尝试备用流或下一候选源时，必须通过主屏状态文案或轻量浮动提示暴露原因，例如“当前源不可用，正在尝试备用流 2/3”，避免无感串台。
- 首页精选集应作为可自定义 seed data：默认包含 UFM 100.3、Radio Paradise、FluxFM Chillhop、KEXP、NTS Radio、ABC Double J 等高质量启动包；每个精选电台必须内置明确 `countryCode`，用于主屏左上角地区入口和地图国家目录路由；每个默认精选必须至少配置一个实测可播放主源，优先补充同台或同氛围备用流，且每次发版前运行 `qa/run-cp17-stream-health.ps1` 复测源健康。默认源优先级按“多轮成功率、同台一致性、音质、响应速度、ICY metadata 能力”排序：UFM 100.3 V1 使用 StreamTheWorld MP3 96kbps 作为主源，AAC / AAC_SC 作为备用；Radio Paradise 使用 AAC 128 作为主源，MP3 320 / MP3 128 作为备用；KEXP 使用 AAC 160 作为主源，AAC 64 作为弱网备用；ABC Double J 使用 NSW HLS 作为主源，VIC / QLD / WA HLS 作为备用。SomaFM Groove Salad 在 2026-07-06 本地网络下官方 PLS 解析出的 ice 节点全部不可出音频，暂不作为默认精选，后续可在公共目录或用户自定义中保留。正式版应允许用户在本地替换、排序、删除或手动添加 stream URL。
- 出厂精选电台的 `region` 是面向用户的显示地点，中文界面下必须使用中文地名，例如 `新加坡 / 加州 / 柏林 / 西雅图 / 伦敦 / 澳大利亚`；底层 Radio-Browser `state`、查询参数、经纬度和 `countryCode` 可继续保留英文或标准代码。不得让主屏顶部地区、调谐区、通知栏/媒体会话和声音明信片之间出现 `Australia` / `澳大利亚` 这类混用。
- 首页精选和 Radio-Browser 转换出的播放项必须尽量保留 `geoLat / geoLong` 坐标元数据；坐标用于地图 marker、公网落地页参数、信号源时间估算和声音明信片回执。无坐标电台允许继续播放，但不得伪造精确坐标。
- 首页电台库必须支持零后端的本地流健康管理：用户可标记某电台主源不可用、添加备用流 URL；播放前应避开本机已标记坏源，主源不可用且有备用流时优先使用备用流。坏源报告、社区审核和公共备用流分发属于后续远端能力，不能在本地原型中伪装为已实现。
- V1.1 本地增强能力包括全局 Radio-Browser 搜索、M3U/JSON/URL 播放列表导入、睡眠定时、声音明信片系统分享和轻量歌词显示；这些能力应收纳在选项、二级面板或低噪音预览中，不能常驻首页破坏精密仪器主视觉。
- 独立信号 `Independent Signals` 是本地人工策展种子库，用于沉淀 independent / community / college / freeform radio 等高品味电台；入口应收纳在设置或发现二级页，不进入首页默认推荐墙。首批条目必须经过 Radio-Browser 或电台官方 playlist / stream 验证，保留 stream URL、fallback、国家码、坐标、质量标签、来源说明和编辑短评；未通过当前网络探测的 KCHUNG、Rytmabad、Norrrm、Mouthful Radio、UCT Radio 等只进入 watchlist，不伪装为可播放条目。独立信号点播后可加入首页电台库并播放，但首页仍坚持“少量精选 + 用户自定义”的克制结构。
- 语言信号 `Language Signals` 是参考公共目录 App 后保留的二级探索能力，用于按华语、英语、日语、德语、法语、西语等语种发现稳定直播；入口应收纳在设置 / 收听分组，不进入首页默认推荐墙。中文入口必须优先 UFM 100.3 或同等稳定华语直播，再补 Radio-Browser 远端结果；其它语种可优先使用现有精选台，再接公共目录质量排序结果。语言信号点播后可加入首页电台库并播放，但不得把首页改成海量语种目录。
- Now Playing 必须是二级沉浸模式，不替代首页仪表盘；用户点击主频率卡或当前曲目后进入。该层可承载封面、当前曲目、歌词、播放/暂停和轻量切台控制，未来 WebDAV / AList / NAS / 本地音乐库也必须复用同一套 Now Playing，而不是另起一个普通音乐播放器首页。
- 歌词显示必须由真实 ICY 或官方 Now Playing 当前曲目触发，不能拿出厂兜底文案误查；首页完全不显示歌词，完整滚动歌词只放入 Now Playing 二级层。允许在首页播放期间后台预取，使进入 Now Playing 后无需重新等待。V1.1 原型采用 LRCLIB 公共歌词源和本地时间轴校准；LRCLIB 直接查询未命中时，允许使用 MusicBrainz 公共音乐元数据解析简繁体标题、艺人英文名和正式发行标题，再回查 LRCLIB。MusicBrainz 只提供匹配元数据，不作为歌词来源。不得接入网易云、QQ 音乐等未授权私有灰色接口；正式商业版歌词授权与 provider 合规性为 **待人工确认**。开源歌词 Beta 必须提供用户开关，关闭后不得发起 LRCLIB 或 MusicBrainz 查询；空结果和暂时性错误不得永久缓存。
- V2 私人微电台必须保持“收音机表达”：用户把 WebDAV / AList / NAS / 本地目录绑定为 `NET · PRIVATE STATION`，音频元数据优先读取本地标签、同目录封面和同目录 `.lrc`，在线歌词只作为兜底；不得把 CP17 主界面改造成文件管理器或普通歌单播放器。V2.0 以 WebDAV、AList WebDAV 和 NAS SMB 为正式 provider：WebDAV 使用 `PROPFIND Depth: 1`；NAS 使用 `dart_smb2 / libsmb2` 协商 SMB 2.02 至 3.1.1，禁止 SMB1，可选强制 SMB3 加密和签名。SMB 只允许局域网、单标签 NAS 主机、`.local` 和 Tailscale `100.64.0.0/10`，不得鼓励公网暴露 445。NAS 扫描最多递归 8 层 / 2000 个资源，识别 MP3、AAC、M4A、FLAC、OGG、OPUS、WAV，并按同目录与同名规则关联 `.lrc` / 封面。Android 密码或 Token 必须用 Keystore AES-GCM 加密，普通 SharedPreferences 只能保存名称、provider、地址、目录、账号、域和非秘密安全选项。播放凭据只允许在内存中传给 `AudioHandler`，不得进入 `PlaybackItem`、`MediaItem.extras`、日志、分享链接或 Git。SMB 音频通过仅监听 `127.0.0.1` 的随机令牌 Range 网关交给 `just_audio`，不得整首落盘或把凭据嵌入 URL。私人目录点播必须复用现有后台媒体会话和 Now Playing，队列切歌后首页、通知栏和歌词层必须同步当前曲目。
- V1.2 地图在低缩放级别必须聚合邻近 marker，点击聚合点只负责放大定位；展开后的单个 marker 才进入现有电台置顶卡和显式播放流程，禁止点击地图点后无提示自动播放。
- 分享回流必须校验 scheme、host 和 HTTPS 音频地址。外部链接只能导入并选中电台，不得在用户未点击播放时自动启动第三方直播流。
- 首页横向预设最多承担少量精选和当前地区快切，不承担大量收藏管理。完整收藏必须进入二级收藏列表，支持搜索、当前台标记、显式切台和取消收藏；取消收藏不得顺带删除用户电台源。
- 播放器必须以用户点击触发播放，不能依赖自动播放；`playMediaItem` 只负责切换当前媒体项，真实起播由 UI 或系统 `play` 命令触发，避免地图点播、快切和通知栏动作重复拉流；直播流连接失败时必须给出轻量状态反馈，不能假装播放成功。
- 切台、备用流重试和地球背面跳转进入拉流 / buffering 时，允许播放 1 秒左右的本地“虚空寻台”底噪作为仪器反馈；底噪必须低音量、短时、可被真实电台声音自然覆盖，且不进入媒体会话、不影响播放/暂停状态、不循环常驻。主流 ready、暂停、停止、候选耗尽或用户切换离开时必须立即停止底噪；后续正式版应提供关闭开关。
- Android 真机音频流测试可以先用 Capacitor WebView 打包现有 Web 原型，保留 `<audio>` 播放链路和真实 `streamUrl`；该 APK 仅作为播放体验、网络流兼容性和 Android 16 适配 smoke test，不等同于正式原生音频架构。
- 本机 Codex 测试环境已固定使用 Android SDK/JDK 缓存目录 `C:\Users\matz\.cache\codex-android`，历史可用 AVD 为 `CP17_API35_COMPACT`（Android 15 / API 35 / medium_phone / 720x1600）和 `CP17_API36`。但当前宿主机已多次出现 QEMU / Android Emulator 崩溃、显卡/虚拟显示链路异常和黑屏重启风险，因此默认回归不得启动 emulator / QEMU。正常开发只运行 `qa/run-cp17-safe-regression.ps1`；模拟器脚本仅作为受控排障入口，必须显式传入 `-AllowQemuRisk` 或设置 `CP17_ALLOW_QEMU_RISK=1` 后才能启动。`CP17_API35_STABLE + host GPU`、`CP17_API35_MEDIUM` 已标记为历史方案，不再作为主力验收依据；真实声音、定位和系统级能力以 Android 真机 L3 结果为准。
- 附近电台能力正式实现时，定位只用于本地筛选和城市推荐；Android APK 必须声明并请求 `ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION`，通过 Capacitor Geolocation 或正式原生定位能力获取本机经纬度，权限拒绝时使用默认城市或手动城市选择。
- 地图瓦片、反向地理编码和电台目录都应抽象为可替换 provider；当前 Flutter 原型按地区选择 V1 兜底瓦片：中国大陆使用高德 Web，海外使用本机实测更可用的 OSM DE 主源 + OSM HOT fallback，避免高德海外空白瓦片遮住纸质底图和 marker；失败瓦片按 3 秒、8 秒、15 秒退避重试，断网时保留已显示瓦片、抽屉和缓存电台。地图来源只在标题副标题中轻量显示，不得再用全宽悬浮来源条遮挡地图。瓦片缓存不得用普通图片缓存粗暴替代 `flutter_map` 的瓦片 provider；如需缓存，应在 `Cp17MapProvider` 层接入专用 TileProvider / tile cache manager，或使用正式地图 SDK 自带缓存能力。正式 Flutter App 必须接入真实地图 SDK 或成熟地图组件，支持缩放、拖拽、marker 经纬度投影和定位 camera；中国大陆优先使用百度/高德等本地 provider，海外优先使用 Google Maps 或同等级 provider，并在 provider 层处理 WGS84、GCJ-02、BD-09 坐标转换。
- 地图上的渐变、边框、光感等视觉覆盖层必须使用 `IgnorePointer` 或等价方式，不能拦截地图拖拽、缩放、marker 点击和抽屉手势。
- 收藏、主题选择、睡眠定时等用户设置必须本地持久化。
- 首次安装默认主题为“暖金石墨 / Warm Gold Graphite”；已有用户已经持久化的明确主题选择不得被升级覆盖。暖金石墨以中性炭黑为大面积底色，香槟金仅用于交互强调和信号状态，不扩张为棕橙色单色界面。
- 外观主题允许提供一套更接近大众音乐播放器可读性的“明亮信号 / Luminous Signal”可选方案：使用石墨海军蓝背景、提亮的蓝灰功能面、天青信号色和清晰控件边界，首页布局、仪器调谐逻辑和地图低饱和原则保持不变。该主题不得复制第三方应用素材，不使用彩色电台 Logo 墙，不扩张成高饱和蓝色娱乐化界面。
- Flutter 主题实现采用 `ColorScheme + ThemeExtension` 分层：`_VoidPalette` 维护基础与语义色，`_VoidComponentTokens` 维护首页背景、快捷控件、频道、调谐、播放控制和阴影等高复用组件令牌。组件不得按主题名称写条件分支；新增主题应只新增令牌映射。历史页面中的硬编码颜色应在触达修改时逐步迁移，不要求一次性高风险重写。
- 声音明信片正式实现必须使用专用分享画板，不直接截取整屏；Flutter 方案采用 `RepaintBoundary`、`path_provider` 和 `share_plus`，输出高清 PNG 后再调起系统分享。
- 公网落地页 V1 必须保持零后端静态实现，通过 URL 参数承载 `station / place / freq / stream / fallback / now / mode / story / lat / lng / app`，页面只负责展示 Void Radio 声音卡片和原生音频播放器。移动端浏览器必须由“立即收听”按钮显式触发 `audio.play()`，不得依赖自动播放；主流失败时可在同一次用户播放意图下顺序尝试 `fallback` 备用流，并保留原始直播流降级入口。正式域名不是 MVP 前置条件；可先使用 Cloudflare Pages、Vercel 或 GitHub Pages 的 HTTPS 地址，后续再绑定自有域名和深链。如复用 `feedar.cc`，优先使用 `listen.feedar.cc` / `radio.feedar.cc` 等子域名，不直接影响现有交易系统。

## 质量门禁

- CP17 后续任意新版本、热修、APK 打包、UI 调整、音频链路修改、地图/Radio-Browser 数据改动，都必须按 [[CP17_版本回归测试规则]] 执行对应等级回归；未完成回归不得交付给用户体验。
- 局部 UI 调整必须优先读取 [[CP17_UI基线与版本差异]]，再对当前工作树与记录的基线 commit 执行最多一次目标目录 diff；禁止默认逐个 `git show` 或遍历 Git 历史。只有索引缺失、commit 不可解析、当前实现与基线截图冲突时，才允许继续查询历史。完成后使用 `qa/update-cp17-ui-baseline.ps1` 生成 Git 事实摘要，并人工补充尺寸、截图和视觉验收结论。
- 当前宿主机的最低安全放行标准为：`qa/run-cp17-safe-regression.ps1` 通过，即 `dart format`、`flutter analyze`、`flutter test`、`flutter build apk --debug` 和 APK 留档复制全部完成，且不启动 Android emulator / QEMU。
- 首页精选电台源地址变更、默认频道调整或发布候选包冻结前，必须运行 `qa/run-cp17-stream-health.ps1`，确认所有默认精选主源可出音频，备用源按“可用性、音质、同台一致性、响应速度”排序；公共流短时失败时必须记录本轮 JSON/Markdown 报告路径和降级决策。
- L1 模拟器 smoke 不再是本机默认动作；只有在明确接受 QEMU 风险时，才运行 `qa/run-cp17-l1-regression.ps1 -AllowQemuRisk`。该脚本会两段式调用 smoke：phase1 验证首页、床头钟和国家切换，phase2 验证附近地图、抽屉展开和地图点播；并只对 emulator 离线、`error: closed`、System UI ANR 等环境失败做有限重试，UI/播放断言失败不得被重试掩盖。
- 有模拟器或真机截图时，必须保留首页、床头钟、国家切换地图、地图默认态、地图抽屉展开态、地图点播回主页截图和 summary；自动化通过后仍需人工复核截图。
- 地图点播回主页后不得停留在 `READY / 已接入 · 点击播放 / 已暂停`；公共流失败可以接受，但必须显示连接中、直播中或明确播放失败。
- 选项面板在小屏必须可访问所有入口；床头钟、睡眠定时、声音明信片不得被底部截断。
- Android 16 真机到位后，发布候选包必须补齐真机 L3 回归：真实播放、定位权限、系统分享、熄屏/后台 30 分钟不断流、锁屏/通知栏控制、蓝牙/耳机按钮、Wi-Fi/移动网络切换和断流恢复。真机 L3 结论优先级高于本机 emulator。
- 任何变更如果影响产品能力、交互、数据来源、权限、稳定性或测试口径，必须同步更新核心说明、功能说明和测试用例；文档未同步视为未完成。

## 商业化原则

- 基础播放、调频、收藏少量电台应保持可用，保证“干净无广告”的基础体验。
- 高级版适合承载：自动 Shazam、横屏/桌面时钟主题库、天气主题、直播回放/录音、CarPlay、无限收藏。
- 海外传播素材应优先展示 10-15 秒真机滑动刻度盘和待机时钟切换，而不是长文功能介绍。

## V1.1.2 发布稳定性补充（2026-07-11）

- App 内置精选与独立信号只允许使用 Android 可直接消费的 HTTPS 音频直链或 HLS；统一通过 `StreamCompatibility` 过滤，拒绝 HTTP、`.pls`、`.m3u` 和不可解析的间接播放列表。Radio-Browser、语言信号、手工添加、播放列表导入和备用源必须采用同一规则，不能各自放宽。
- 独立信号属于版本管理的内置策展数据。覆盖升级时，同 ID 的旧内置定义必须迁移到当前版本主备源，同时保留用户排序、收藏和当前选择；`curated_independent` 不得被误存为普通自定义电台快照。
- 内置流发版门禁同时运行 `tools/probe_void_radio_streams.py --timeout 12 --retries 2` 和 `qa/run-cp17-independent-signal-health.ps1`。探测器允许有限重试以吸收单次 TLS 握手抖动，但最终失败仍必须返回非零；2026-07-11 结果为全部内置主备流 `38/38`、独立信号 `22/22` 通过。
- 中国高德 Web 瓦片使用 GCJ-02 投影，Radio-Browser 和系统定位的 WGS84 坐标在进入地图渲染前转换；海外 OSM 保持 WGS84。marker、地图中心和用户定位点必须走同一投影函数，避免“底图正确但点位偏移”。地图必须显示 provider 版权文案。
- 地图电台 marker 必须暴露“地图电台：名称”语义标签；真机回归按语义节点选点，不再使用缩放和平移后会失效的固定坐标。点击 marker 后显示锁定卡、把电台置顶到抽屉并由用户确认收听。
- Android 13+ 首次播放前请求通知权限；后台播放服务声明 `mediaPlayback` 且 `stopWithTask=false`。发版真机门禁至少覆盖 Home、锁屏、系统媒体键和完整快捷设置媒体卡的暂停/恢复。
- Motorola `com.motorola.deviceguard` 在用户划掉最近任务时可能执行 `forceStopPackage`。系统 force-stop 会终止前台服务，应用代码无法规避；该行为不作为 moto G55 的版本阻塞，但必须作为 OEM 已知限制告知用户，可建议锁定最近任务或关闭系统自动清理。
